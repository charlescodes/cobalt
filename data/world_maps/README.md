# World Map Generation

This directory is for saved runtime World editor maps. A saved world map is a `WorldMapData` resource, separate from local editor `MapData` resources.

The saved resource stores generator inputs. The terrain mesh, colors, elevation, moisture, and temperature buffers are regenerated from those inputs when the map is loaded or rebuilt.

## Runtime Data Shape

World maps use a dedicated top-level container:

```text
WorldMapData
- map_id
- geology
```

For the current world-editor slice:

- `geology` is required and stores all generator parameters.
- World maps do not persist `grounds`, `static_walls`, `door_sockets`, or `world_objects`.
- `GeneratedMap/WorldPickSurface` is derived at runtime from `geology.size_m`; it is not saved.
- The visible surface is regenerated by `WorldGeologyGenerator` and rendered by `WorldMapBuilder` as `GeneratedMap/WorldMap3DLayer`.

Local editor maps save under `res://data/editor_maps/`. World maps save under `res://data/world_maps/`.

## WorldGeologyData Inputs

`WorldGeologyData` is the durable source of truth for the generator:

```text
seed_text
size_m
map_scale_km
coast_enabled
coast_edge
roughness
sea_level
global_temperature
base_rainfall
wind_direction_degrees
erosion_strength
vegetation_spread
tree_canopy_density
tectonic_alignment_degrees
toxicity
```

Important scale conventions:

- `1 Godot unit = 1 meter`.
- `size_m` is stored as meters. The current World Ground UI clamps X/Z from `250000` to `1000000`, or 250km to 1000km.
- The default world is `500000m x 500000m`.
- The generated visible mesh uses real meter coordinates centered at origin.
- Land visual height is capped at `9000m`.

## Generation Pipeline

The generator lives in `res://src/generation/world_geology_generator.gd`.

`WorldGeologyGenerator.generate(geology_data, grid_resolution := 65)` returns a dictionary of runtime buffers:

```text
resolution
size_m
vertices
colors
indices
elevation
moisture
temperature
```

The default grid is `65 x 65`, or 4225 vertices. The resolution is clamped to `9..129` if a caller asks for another size.

### 1. Seed And Noise Layers

The seed text is hashed with an FNV-style integer hash. The resulting seed drives four deterministic `FastNoiseLite` layers:

```text
base terrain noise      seed
tectonic ridge noise    seed + 1009
moisture noise          seed + 2039
toxicity noise          seed + 4093
```

Noise frequency is inversely related to `map_scale_km`, so larger map scales produce broader features.

### 2. Elevation

Elevation starts as a normalized `0.0..1.0` grid.

For each cell:

```text
km_x = centered x coordinate in kilometers
km_z = centered z coordinate in kilometers

base = simplex FBM noise sampled at km_x, km_z
ridge = ridged noise sampled after rotating coordinates by tectonic_alignment_degrees

elevation = (base * 0.54) + (ridge * roughness * 0.46)
```

If coast is enabled, the chosen edge lowers nearby elevation:

```text
elevation -= coast_influence * 0.48
```

`coast_influence` fades from the chosen edge over about 24% of the normalized map width/depth using smoothstep.

Final elevation is clamped to `0.0..1.0`.

### 3. Erosion

The current erosion pass is a simplified smoothing pass, not a full droplet simulation.

```text
iterations = round(erosion_strength * 8)
```

Each iteration averages each non-edge cell against its four cardinal neighbors. Steeper cells blend more strongly toward the neighbor average, with a maximum per-pass blend of `0.65`.

This softens sharp noise peaks and gives the blockout more connected valleys/ridges without expensive simulation.

### 4. Moisture And Rain Shadow

Moisture is also a normalized `0.0..1.0` grid.

The wind direction slider is converted to a 2D wind vector:

```text
wind = Vector2(sin(degrees), -cos(degrees))
```

For each cell, the generator estimates the local elevation gradient with neighboring elevation samples:

```text
gradient.x = elevation east - elevation west
gradient.y = elevation south - elevation north
```

The rain-shadow term is the dot product of wind and gradient:

```text
lift = dot(wind, gradient)
```

Positive lift means the wind is moving upslope, so moisture increases on the windward side. Negative lift means downslope/leeward, so the result becomes drier.

Final moisture:

```text
moisture =
  (moisture_noise * 0.28)
  + (base_rainfall * 0.54)
  + (lift * 3.0)
  + coast_bonus
```

`coast_bonus` is added near the enabled coast edge and fades inland. Final moisture is clamped to `0.0..1.0`.

### 5. Temperature

Temperature is normalized `0.0..1.0` and combines global baseline, latitude, and elevation cooling.

```text
latitude = z / (resolution - 1)
equator_warmth = 1.0 - abs((latitude * 2.0) - 1.0)

temperature =
  (global_temperature * 0.68)
  + (equator_warmth * 0.38)
  - (elevation * 0.34)
```

Final temperature is clamped to `0.0..1.0`.

### 6. Mesh Vertices

Each grid sample becomes one vertex.

```text
x = (normalized_x - 0.5) * size_m.x
z = (normalized_z - 0.5) * size_m.y
```

If `elevation <= sea_level`, the vertex is water and `y = 0`.

If the sample is land:

```text
land_t = clamp((elevation - sea_level) / (1.0 - sea_level), 0.0, 1.0)
y = pow(land_t, 1.35) * 9000.0
```

The mesh is triangulated as two triangles per grid square.

### 7. Biome Color

The current biome system outputs vertex colors, not biome resources.

Water uses a blue depth gradient. Land uses simple threshold bands:

- high elevation becomes alpine/snow color
- low temperature becomes tundra/frozen color
- low moisture becomes desert/dry color
- high plant factor and moderate/high temperature becomes forest/lush color
- medium plant factor becomes grassland/vegetated color
- remaining land becomes scrub/temperate blockout color

Plant factor combines moisture, vegetation spread, tree canopy density, and toxicity:

```text
plant_factor =
  ((moisture * 0.55) + (vegetation_spread * 0.25) + (tree_canopy_density * 0.2))
  * (1.0 - (toxicity * toxicity_noise))
```

Colors are stored in the generated `colors` array and rendered by the world mesh material as vertex albedo.

## Rendering And Selection

`WorldMapBuilder` consumes the generated buffers.

It creates:

```text
GeneratedMap/WorldPickSurface
GeneratedMap/WorldMap3DLayer
```

`WorldPickSurface` is hidden and exists for picking/collision only. It keeps selection and ground resizing simple without rendering a giant grey box. It is rebuilt from `WorldMapData.geology.size_m` and does not correspond to a saved `GroundData` resource.

`WorldMap3DLayer` is render-only:

- no editor selection metadata
- no collision shape
- unshaded material
- vertex colors used as albedo
- backface culling disabled
- explicit macro custom bounds
- shadow casting disabled

World ground selection is data-only. The editor intentionally does not create a macro-scale highlight shell.

## Current Gaps

Implemented now:

- deterministic seed-driven geology
- coast edge lowering
- rough base terrain and ridged mountain ranges
- simplified erosion smoothing
- directional rain-shadow moisture
- latitude/elevation temperature
- vertex-color biome blockout
- separate `WorldMapData` resource type
- visible 3D macro mesh plus hidden pick surface

Not implemented yet:

- saved biome resources per cell
- zones, region ids, roads, rivers, routes, towns, or points of interest
- generated local-map seeds from selected world zones
- full hydraulic droplet erosion
- selectable per-cell/zone handles on the world mesh
